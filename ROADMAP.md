# AWA Open-Source Roadmap

## Purpose

This roadmap communicates project direction, not guaranteed delivery dates.

## Current Foundation

- Sanitized source snapshot.
- Clean local Git history.
- Licence and governance preparation.
- Reviewed architecture documentation.
- Local mock/development configuration.
- Backend and frontend source.
- Tests and CI workflow retained for validation.

## Phase 1 — Documentation and Contributor Readiness

- Final technical README.
- MCA major-project context.
- Architecture and workflow explanation.
- Feature-status matrix.
- Development setup.
- Selected synthetic screenshots.
- Independent portfolio-project links.
- Private security and conduct reporting channels.

## Phase 2 — Reproducible Validation

- Dependency installation from lockfiles.
- Frontend lint and build.
- Backend test suite.
- Playwright validation.
- Docker Compose validation.
- Migration validation.
- Dependency and licence review.
- Reproducible CI repair.

## Phase 3 — Release Engineering

- Versioning policy.
- Release checklist.
- Branch protection.
- Required CI checks.
- Secret scanning and push protection.
- Dependency update automation.
- Signed or verified release process where practical.

## Phase 4 — Community Development

- Documentation.
- Accessibility.
- Localization.
- Provider abstraction.
- Test coverage.
- Deployment guidance.
- Observability.
- Performance benchmarking.
- Security hardening.

## Known Limitations

- No verified public-production deployment.
- No stable release.
- External provider credentials and setup required.
- No email/SMS reminder delivery where unsupported.
- Live payment behavior not independently verified.
- No uptime or compliance guarantee.
- Operational backup, restore, paging, scale, and deployment validation remain
  environment-dependent.

## Non-Commitments

Roadmap items are proposals. Ordering may change, inclusion does not guarantee
implementation, and no delivery date or support SLA is promised.
